# Use cases — what the stack enables

Each file in this directory is a buildable spec: inputs (exact repo artifacts),
behavior, honesty rules, phases. Nothing here needs new data — only wiring.

| Spec | One line |
|---|---|
| `chatbot.md` | Gate-aware Trika tutor over the corpus |
| `embeddings-loop.md` | **Core:** pushing Q→GEM as seed questions, human questions appended, per-text and multi-text chat (nibbanahelp relay pattern) |
| `translation-workbench.md` | Human-in-loop accept/reject, witnesses, variations, custom translations |
| `pushing-service.md` | The method pointed at any text |
| `curriculum.md` | Essays + passages + cruxes + scholars as guided stages |
| `recitation-app.md` | Standalone chant PWA from the player + chants |
| `citation-graph.md` | Verse → witnesses → scholars, researcher view |
| `embeddings-api.md` | Versioned, gate-labeled, license-tagged corpus product |

Endgame order: chatbot → workbench (carries accounts) → pushing-service.
Instructional-practice line (guided exercises): cross deliberately, not accidentally —
the site contract is display-only.
